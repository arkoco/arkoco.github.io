兼容不等于不用改

迁移清单上第一行是连接串，jdbc:mysql:// 换成 jdbc:oceanbase://。改完这一行，项目能起来，大部分 SQL 也照跑。

真正花时间的在别处：在代码里搜旧库名，一条一条看命中。

OceanBase 的 MySQL 模式兼容的是语句。语句之外那些耦合，一样要改。

先搜库名，再谈语法​

代码里写死 库名.表名 的地方比想象中多。Mapper 的 XML、拼出来的 SQL 片段、存储过程、定时任务的配置表，都会带上前缀。

库名一换，这些地方全部要跟着换。全局替换能干掉大部分，剩下的得人看：有的把前缀和后缀分开拼，搜整串搜不到。

先确认库名是不是非改不可。OMS 做结构迁移时，会自动在目标端创建源端不存在的库，库名原则上可以保持一致。保持一致，这一整轮搜索就省了。

非要改的话，注意大小写。OMS 的迁移手册里写着，默认按目标端 lower_case_table_names = 1 建对象，表名一律小写。代码里如果有驼峰表名，会静默对不上。

兼容清单要按版本拉​

拿别人的踩坑清单当自己的清单，是最容易出事的一步。同一份「不支持」列表，OB 3.x 和 4.x 差得很远。

3.x 的清单里，GET_LOCK()、SHA2()、ENUM、空间数据类型都在不支持那一侧。4.6 的清单短得多，只剩几项：

  • 字符串函数的 MATCH()，以及原生语义的 LOAD_FILE()
  • XML 函数的 ExtractValue() 和 UpdateXML()
  • MASTER_POS_WAIT()
  • SELECT ... FOR SHARE

落到具体项目上，大部分语法是通的，需要适配的往往只有一两处小众写法。这几处最好拿真实 SQL 在目标租户上跑一遍，别靠清单推断。

另一个方向的差异也得记一笔。OB 实现了 information_schema 和 mysql 里的大部分视图，但不保证全都有，列的含义也可能和 MySQL 不同。有监控 SQL 查这些视图的，得单独验。

分页方言是最容易漏的一处​

MyBatis 项目基本都挂 PageHelper。它靠 JDBC URL 判断方言，PageAutoDialect.fromJdbcUrl 拿 URL 去匹配一张别名表。

表里有 mysql、oracle、postgresql，没有 oceanbase。连接串一换成 jdbc:oceanbase://，分页就直接抛 使用 PageHelper 分页插件时，必须设置 helper 属性。

SQL 本身没问题，是插件认不出你连的是什么库。

单数据源，在配置里写死方言最省事：

pagehelper:
  helper-dialect: mysql

多数据源、要在 OB 的 Oracle 模式和 MySQL 模式之间切，就注册一个别名，把 oceanbase 映射到 MySQL 的方言实现：

PageAutoDialect.registerDialectAlias("oceanbase", MySqlDialect.class);

这两条都不是文档里写着的，得看 PageAutoDialect 的源码，或者 PageHelper 仓库里那个问「如何适配 OceanBase」的 Issue。

统计信息得重新收​

迁移完最容易漏的是统计信息。MySQL 那边攒下来的行数估算和直方图，不会跟着数据一起过来。

OMS 的文档在全量校验前专门提了一句：建议两端各收集一次统计信息。不做这一步，OB 优化器手里没有可用的估算，大表关联的执行计划很容易走偏。

看计划的方式也不一样。EXPLAIN 的输出只有 ID、OPERATOR、NAME、EST. ROWS、COST 这几列，SHOW WARNINGS 拿不到额外信息，想看细的要用 DBMS_XPLAN。

参数这块没有通用清单。OB 的内存、CPU、并行度是租户级的，不像 MySQL 那样改一行 my.cnf 就生效。照搬过去的参数文件，大概率是白改。

代价​

上面讲的都是单库。真正的成本不在这几处改动上，在验证覆盖面。

字符集和排序规则是最隐蔽的一项。源端 utf8mb4_0900_ai_ci、目标端 utf8mb4_general_ci 的话，'A' 和 'A ' 在 MySQL 里是两条，到 OB 里会被判成重复，写入直接丢一条。OMS 文档把这条列成了已知风险。

预检查也会挡人。主键是 FLOAT 或 DOUBLE 的表，预检查直接失败。不是迁移出错，是它压根不让过。

还有一类：项目越依赖 MySQL 的高版本特性，改造越大。JSON 函数、全文索引、空间类型，在 OB 里要么换一套写法，要么没有。

原来是 Mycat 分库分表的，另有一层发号的问题，见 Mycat 的自增主键挡住了回滚。

回到那行连接串​

那行连接串是整场迁移里改动最小的一处，也最容易让人以为改完了。真正决定工期的，是搜索 旧库名. 之后命中的数量，和需要人看的那几屏。
